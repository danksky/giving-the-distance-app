# Sponsor Matching System (v0)

This document describes the sponsor matching system that automatically matches Strava activities with sponsor campaigns.

## Overview

The sponsor matching system is a proof-of-concept (v0) that:

- Automatically matches incoming Strava activities with available sponsor campaigns
- Updates Strava activity descriptions with sponsor messages
- Tracks budget decrements and charity commitments
- Ensures idempotency (activities are only matched once)

## Architecture

### Database Models

#### Sponsor

Represents a business that sponsors activities.

- `id`: Unique identifier (matches JSON file slug)
- `name`: Display name
- `businessName`: Official business name
- `slug`: URL-friendly identifier
- `website`: Business website (optional)
- `address`: Business address as JSON (optional)

#### Campaign

A sponsor's campaign with a budget for matching activities.

- `id`: Unique identifier
- `sponsorId`: Foreign key to Sponsor
- `name`: Campaign name
- `budgetRemainingCents`: Current remaining budget in cents
- `isActive`: Whether the campaign is currently active

#### CampaignTopUp

Records of budget additions to campaigns.

- `id`: Unique identifier
- `campaignId`: Foreign key to Campaign
- `amountCents`: Amount added to budget in cents
- `notes`: Optional notes about the top-up
- `createdAt`: When the top-up occurred

#### SponsorMatch

Tracks every attempt to match an activity with a campaign.

- `id`: Unique identifier
- `activityId`: Foreign key to Activity (unique for idempotency)
- `stravaActivityId`: Strava activity ID (also stored for reference)
- `athleteId`: Foreign key to StravaAthlete
- `stravaAthleteId`: Strava athlete ID (also stored for reference)
- `campaignId`: Foreign key to Campaign (nullable if no match)
- `result`: Enum of possible outcomes:
  - `MATCHED`: Successfully matched and description updated
  - `SKIPPED_NO_BUDGET`: Campaign has insufficient budget
  - `SKIPPED_NO_ACTIVE_CAMPAIGN`: No active campaign available
  - `SKIPPED_ALREADY_SPONSORED`: Activity already has a sponsor match
  - `SKIPPED_NO_SELECTED_CHARITY`: No selected or default charity was available
  - `SKIPPED_UPDATE_FAILED`: Failed to update Strava description
- `decrementCents`: Amount deducted from budget (0 if not matched)
- `notes`: Optional notes about the match

#### CharityCommitment

Tracks charity donations generated by sponsor matches.

- `id`: Unique identifier
- `userId`: Foreign key to User
- `charityId`: Foreign key to Charity (user's selected charity at time of match)
- `campaignId`: Foreign key to Campaign
- `activityId`: Foreign key to Activity
- `amountCents`: Commitment amount (typically 10 cents)

### Constants

- **COMMITMENT_AMOUNT_CENTS**: 10 (i.e., $0.10 per activity)
- **GTD_MARKER**: `#GTD` (marker to prevent duplicate description updates)

## Matching Algorithm

### Step 1: Idempotency Check

Check if the activity already has a sponsor match. If yes, return `SKIPPED_ALREADY_SPONSORED`.

### Step 2: Find Active Campaign

Find an active campaign with sufficient budget:

- `isActive = true`
- `budgetRemainingCents >= COMMITMENT_AMOUNT_CENTS`

For v0, randomly select from available campaigns.

If no campaign found, create sponsor match record with `SKIPPED_NO_ACTIVE_CAMPAIGN` and stop.

### Step 3: Budget Check

Verify campaign has enough budget for the commitment amount.

If insufficient budget, create sponsor match record with `SKIPPED_NO_BUDGET` and stop.

### Step 4: Verify User Has Selected Charity

Ensure the user has a persisted `selectedCharityId`.

If the user is missing one, the system first attempts to assign the platform default charity automatically.

If no selected or default charity can be resolved, create a sponsor match record with `SKIPPED_NO_SELECTED_CHARITY` and stop.

### Step 5: Update Strava Description

1. Fetch current activity details from Strava API
2. Check if description already contains `#GTD` marker
3. If marker present, skip update (already processed)
4. Build sponsor message:
   ```
   This [activity_type] inspired a donation by Giving the Distance, sponsored by [Sponsor Name] - [website] #GTD
   ```
5. Append message to existing description
6. Update activity via Strava API

If update fails, create sponsor match record with `SKIPPED_UPDATE_FAILED` and stop.

### Step 6: Create Records (Transaction)

In a database transaction:

1. Decrement campaign budget by `COMMITMENT_AMOUNT_CENTS`
2. Create sponsor match record with `MATCHED` result
3. Create charity commitment record

## Setup

### 1. Database Migration

Push the schema changes to your database:

```bash
npm run db:push
```

### 2. Seed Sponsors and Campaigns

Run the seed script to load sponsors from JSON files and create default campaigns:

```bash
npm run db:seed
```

This will:

- Load all charities from `data/charities.json`
- Load all sponsors from `data/sponsors/*/profile.json`
- Create a default campaign for each sponsor with $100.00 initial budget
- Create an initial top-up record for each campaign

### 3. Webhook Integration

The webhook handler (`app/api/strava/webhook/route.ts`) automatically calls the sponsor matching service for new activities.

## Current Limitations (v0)

1. **No Activity Filtering**: All activities are eligible for matching (no type, distance, or location filters)
2. **Random Campaign Selection**: Campaigns are randomly selected when multiple are available
3. **Fixed Commitment Amount**: All matches generate $0.10 commitment
4. **No Rate Cards**: No variable pricing based on activity characteristics
5. **No Geographic Targeting**: No neighborhood or location-based matching
6. **Single Campaign per Sponsor**: Each sponsor has only one default campaign

## Future Enhancements

- Activity filtering (by type, distance, location)
- Intelligent campaign selection (round-robin, weighted, etc.)
- Variable commitment amounts based on distance or other factors
- Multiple campaigns per sponsor with different targeting rules
- Geographic/neighborhood-based matching
- Sponsor-specific rate cards
- Campaign scheduling (start/end dates)
- Budget alerts and notifications

## API Reference

### `matchActivityWithSponsor(activity, accessToken)`

Main function to match an activity with a sponsor campaign.

**Parameters:**

- `activity`: ActivityData object containing activity details
- `accessToken`: Valid Strava OAuth access token

**Returns:** MatchingResult object with:

- `success`: boolean indicating if match was successful
- `result`: SponsorMatchResult enum value
- `sponsorMatchId`: ID of created sponsor match
- `charityCommitmentId`: ID of created charity commitment (if successful)
- `campaignId`: ID of matched campaign
- `message`: Human-readable message
- `error`: Error message (if failed)

### `hasExistingSponsorMatch(activityId)`

Helper function to check if an activity already has a sponsor match.

**Parameters:**

- `activityId`: Internal activity ID

**Returns:** boolean

## Monitoring and Debugging

### View Sponsor Matches

Use Prisma Studio to view sponsor matches:

```bash
npm run db:studio
```

Navigate to the `sponsor_matches` table to see all matching attempts and their results.

### View Campaign Budgets

Check the `campaigns` table to see remaining budgets for each campaign.

### View Charity Commitments

Check the `charity_commitments` table to see all generated donations.

### Webhook Events

The `strava_webhook_events` table tracks all incoming webhook events and their processing status, including whether the description was updated and any errors encountered.
